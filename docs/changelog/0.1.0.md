# 0.1.0

## Added

- Nodo `ai.completion` (categoría **AI**): envía un prompt a un proveedor
  externo y emite la respuesta como texto. Espeja la forma del resto del
  catálogo — escalar → escalar, array → array paralelo con una llamada
  por elemento y `concurrency` como límite de peticiones en vuelo.
  Kinds de wire: `openai` (OpenAI-compatible, con `Base URL` para Groq /
  OpenRouter / Ollama / LM Studio) y `anthropic`. El proveedor y su endpoint
  se declaran en el catálogo global, no en el nodo (ADR-005).
- `ai.completion` acepta una segunda entrada `Data` (tipo `any`) además
  de `Prompt`. Si el prompt contiene `{{data}}` se sustituye en su sitio;
  si no, los datos se añaden tras una línea en blanco. Un array de datos
  implica una llamada por elemento (broadcast / emparejado / error por
  longitudes distintas). Contrato funcional en
  [`SPEC/decisions.md`](../SPEC/decisions.md) (FD-001).
- Capa `src-tauri/src/ai/`: `AiGateway` como seam, `RigGateway` sobre
  `rig-core =0.46.0`, reintentos acotados (400/800 ms) solo para errores
  transitorios, y `MockGateway` bajo `#[cfg(test)]`.
- `SecretStore`: catálogo global de proveedores (`id`, `kind`, `label`,
  `base_url`, `models`) y sus claves API en `<app_data_dir>/secrets.json`,
  con migración automática del formato legacy `kind → clave`, escritura
  atómica y permisos `0600` en Unix.
- Comandos Tauri `ai_providers`, `ai_save_provider`, `ai_remove_provider` y
  `ai_clear_provider_key`. Ninguno devuelve la clave; cada proveedor reporta
  `configured` y un hint de 4 caracteres, y todos responden el catálogo
  resultante para que la UI se refresque en un round-trip.
- Diálogo **AI Providers** en la toolbar (CRUD de proveedores, endpoints,
  listas de modelos y claves): única vía de entrada de una clave.
- `ParamField` tipo `textarea` (renderizado en el Inspector) para
  prompts e instrucciones de sistema, y `model` para elegir proveedor + modelo
  del catálogo global.
- Test de integración `ai_node_output_feeds_downstream_split`
  (AI-TEST-006): `literal.string` (fila CSV) → `ai.completion` →
  `string.split` → `array.length` → `io.output`, contra
  `MockGateway` (offline y determinista).
- Panel lateral **Logs** (botón en la toolbar, se abre solo al fallar un
  run): todas las entradas de la última ejecución, con filtro por nivel,
  búsqueda por label / kind / nodo / valor, expansión al JSON completo y
  **Copy** para volcar el run entero como texto.
- `EvalCtx::debug/info/warn/error(label, value)` como API de una línea
  para que cualquier nodo escriba en el log del run; la entrada recuerda
  `node_id` y `kind` automáticamente.
- `LogEntry` gana `level` (`debug|info|warn|error`) y `kind`.
- `io.logger` acepta un param `level` (select) además de `label`.
- `docs/ARCHITECTURE/decisions.md` con las decisiones ADR-001…ADR-005.

- Nodo `http.request` (categoría **IO**): llamada HTTP genérica
  (`GET`/`POST`/`PUT`/`PATCH`/`DELETE`/`HEAD`) con URL, cuerpo y cabeceras.
  Emite `status`, `body` (texto) y `json` (payload parseado o `null`). Un
  4xx/5xx es dato, no fallo del nodo; un error de conexión/DNS/TLS/timeout sí
  falla. Implementado en `executor/nodes/http_request.rs` sobre `reqwest`
  (la misma versión que ya traía `rig-core`).
- Nodo `blueprint.subgraph` (categoría **IO**): incrusta un blueprint guardado
  como un único nodo. Sus puertos se derivan del fichero
  (`metadata.inputs` + un output por cada nodo `Output`, nombrado como él) y
  el nodo se etiqueta con el nombre del blueprint embebido. Al ejecutar, el
  runner carga el fichero, le pasa los valores cableados como inputs
  externos y devuelve sus outputs. Anidamiento permitido hasta 8 niveles.
- Herramientas para `ai.completion`, en dos sabores:
  - **App-level** (toolbar → **AI Tools**): CRUD global de tools HTTP
    (nombre, descripción, JSON Schema de parámetros, método, URL y
    cabeceras) en `<app_data_dir>/tools.json`; el nodo las elige por id
    desde el Inspector y la definición nunca entra al blueprint.
  - **Nodo `ai.tool`**: expone un blueprint guardado como tool. Su salida
    `Tool` se cablea al nuevo puerto `Tools` de `ai.completion` (varios
    nodos se agrupan con `array.create`). Los argumentos del modelo se pasan
    como inputs externos del blueprint y sus `Output` vuelven como JSON.
- Bucle de tool-calling acotado (`Max tool rounds`, 6 por defecto) en
  `ai.completion`: turno del modelo → ejecución de tools → resultado de
  vuelta. Un fallo de tool se reporta al modelo en vez de abortar el run.
  Wire implementado en `ai/providers.rs` con JSON directo para
  OpenAI-compatible y Anthropic (`complete_turn` en `AiGateway`).
- `ParamField` tipos `blueprint` (selector de la librería + ruta manual) y
  `tools` (checklist de tools de aplicación) en el Inspector.
- Nodo `ai.vision` (categoría **AI**): prompt + N ranuras `Image`
  dinámicas (`# Image slots`, botones +/−). Cada ranura acepta una imagen
  base64 (la salida `Binary` de `file.read` / `image.format`) **o un array
  de imágenes**, así que el total de imágenes por petición no está limitado
  por el número de ranuras. Las imágenes se validan como base64 antes de
  llamar al proveedor y el MIME se detecta por magic bytes; el wire es
  `image_url` + data URL en OpenAI-compatible y bloques `image` base64 en
  Anthropic. Un prompt escalar hace una llamada con todas las imágenes; un
  prompt array hace una por elemento con las mismas imágenes.
- `repeatableInputs.mergeFixedInputs` permite que un kind con ranuras
  dinámicas conserve sus puertos fijos (`then_in`, `prompt`) en el canvas y
  en el fichero; `array.create` mantiene el comportamiento anterior.
- `docs/ARCHITECTURE/BACKEND.md` y `FRONTEND.md` documentan los nuevos
  ficheros, comandos y nodos.

- Navegación anidada de subgrafos: desde el cuerpo de un nodo
  `blueprint.subgraph` / `ai.tool` o desde el Inspector se abre el blueprint
  incrustado en el mismo canvas. Una barra de migas muestra la cadena
  completa (raíz › sub › sub-sub), cada ancestro es clicable y **← Parent
  graph** vuelve un nivel. El grafo padre se guarda en la pila con su estado
  sin guardar, de modo que volver no lo pierde. Al volver se invalida la
  caché del subgrafo y se re-derivan los puertos del nodo contenedor. Load y
  New reinician la pila; Save guarda el nivel activo. La migración del
  historial de inputs ya no confunde un salto de nivel con un guardado.
- Volver desde un subgrafo con cambios sin guardar pide confirmación antes
  de descartar el nivel. El aviso compara el nivel vivo con su último
  Load/Save (fingerprint de `composeBlueprint` sin `updated_at`), así que
  guardar, abrir o volver sin editar no dispara el diálogo. `Save` rearma
  la línea base; `Load` y `New` la reinician con el documento nuevo.
- **Group as…** en el Toolbar: guarda los nodos seleccionados como un
  blueprint nuevo y los sustituye en el grafo actual por un nodo
  `blueprint.subgraph` que apunta a ese fichero, colocado en el centroide
  de la selección. Los cables internos viajan con el grupo; cada cable de
  datos que entraba desde fuera se declara como una entrada en
  `metadata.inputs` cuyo id se deriva del nodo emisor y del puerto (con sufijo
  numérico si se repite), y un nodo `blueprint.input` inyectado dentro del
  grupo alimenta al nodo que antes recibía el valor, de modo que el cable se
  reconecta al nodo Subgraph sin perder el dato ni chocar con otro consumidor
  del mismo puerto. Los de salida se reconectan contra `then_out` y los
  `io.output` internos; lo que no tiene contrapartida se descarta. La barra de
  estado informa de cuántos se reconectaron y cuántos se perdieron.
- El Inspector, al seleccionar un nodo `blueprint.subgraph`, lista las
  entradas que declara el blueprint incrustado (id, nombre y tipo), leídas de
  la misma caché `subgraphDefs` que alimenta los puertos del nodo.

## Fixed

- Bucle infinito que congelaba la app al arrancar: el efecto de migración
  del historial de inputs escribía `priorStorage` como objeto nuevo en cada
  pasada, invalidando el estado que él mismo leía. Ahora solo escribe
  cuando cambian la clave o el `bpMeta.id`.
- Los logs de un run fallido se descartaban al devolver `Err`: el
  diagnóstico de los nodos ya ejecutados se perdía justo cuando hacía
  falta. El runner devuelve ahora `RunFailure { error, logs, stats }` y
  `run_blueprint` lo serializa como `RunOutcome` (`ok: false`), que la UI
  pinta en el panel lateral.

## Changed

- `run_graph` es ahora `async` y el comando `run_blueprint` también. Se
  añadió `run_graph_with(bp, inputs, gateway)` para inyectar el gateway;
  `run_graph` sigue existiendo como entrada sin gateway.
- Nuevo registro `setup_async_registry()` en `executor/nodes/mod.rs`.
  `NodeExec` (punteros a función) queda intacto para los 37 nodos
  síncronos.
- `catalog.ts`: categoría `AI` y color propio.
- Los proveedores de IA dejan de configurarse por nodo. `ai.completion` ya no
  expone `provider` ni `base_url` en el Inspector: su param `model` es ahora
  `kind: 'model'` y guarda `providerId::model` elegido del catálogo global
  (toolbar → **AI Providers**). Ver ADR-005.
- Diálogo `AiKeysDialog.svelte` → `AiProvidersDialog.svelte`, y el botón
  **AI Keys** → **AI Providers**. Los comandos `ai_key_status` / `ai_set_key`
  / `ai_clear_key` se sustituyen por los cuatro `ai_providers` /
  `ai_save_provider` / `ai_remove_provider` / `ai_clear_provider_key`, y
  `SecretStatus` por `ProviderStatus`.
- Blueprints guardados antes de este cambio siguen funcionando sin migrar:
  un `provider` (y un `base_url`) que sigan teniendo los params del nodo
  seleccionan el proveedor y el endpoint como antes, y `SecretStore` lee
  también el `secrets.json` en forma legacy. `schema_version` no cambia.

## Known issues

- Una app tool siempre es un endpoint HTTP sin autenticación propia: las
  credenciales, si hacen falta, van en la cabecera `Authorization` de la
  propia tool (el fichero se guarda con permisos `0600` en Unix). No hay
  tools nativas, OAuth ni descubrimiento de esquema.
- Un blueprint embebido se lee de disco en cada ejecución: si el fichero se
  mueve o se elimina, el nodo falla con la ruta en el mensaje. Los puertos
  guardados en el grafo son los últimos que se resolvieron correctamente.
- `cargo test --lib` mantiene 3 fallos preexistentes en
  `executor::nodes::file_iterate_folder` (pasan una ruta de fichero a
  `fs::read_dir`). Ajenos a esta entrega; registrados como PROD-TECH-007.
- El prompt es texto plano: no hay todavía plantillas con variables
  (`{{...}}`) ni salida estructurada (JSON schema).
- No hay cancelación de un run en curso: un `ai.completion` lento bloquea
  el resto del grafo hasta que el proveedor responde o falla.
- Un proveedor sin clave pero con `Base URL` (Ollama, LM Studio) recibe la
  clave de relleno `LOCAL_API_KEY` (`"not-needed"`) porque `rig-core` exige
  una no vacía. Está verificado solo offline: un endpoint local que sí
  autentique reportaría un error de autenticación en lugar del error
  `missing API key` de antes.
- La lista de `models` de un proveedor es orientativa: un nodo puede escribir
  cualquier modelo tras `providerId::` y se envía tal cual. El diálogo no
  consulta el endpoint para descubrimiento (`/v1/models`).
