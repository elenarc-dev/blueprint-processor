# 0.1.0

## Added

- Nodo `ai.completion` (categoría **AI**): envía un prompt a un proveedor
  externo y emite la respuesta como texto. Espeja la forma del resto del
  catálogo — escalar → escalar, array → array paralelo con una llamada
  por elemento y `concurrency` como límite de peticiones en vuelo.
  Proveedores: `openai` (wire OpenAI-compatible, con `Base URL` para
  Groq / OpenRouter / Ollama / LM Studio) y `anthropic`.
- `ai.completion` acepta una segunda entrada `Data` (tipo `any`) además
  de `Prompt`. Si el prompt contiene `{{data}}` se sustituye en su sitio;
  si no, los datos se añaden tras una línea en blanco. Un array de datos
  implica una llamada por elemento (broadcast / emparejado / error por
  longitudes distintas). Contrato funcional en
  [`SPEC/decisions.md`](../SPEC/decisions.md) (FD-001).
- Capa `src-tauri/src/ai/`: `AiGateway` como seam, `RigGateway` sobre
  `rig-core =0.46.0`, reintentos acotados (400/800 ms) solo para errores
  transitorios, y `MockGateway` bajo `#[cfg(test)]`.
- `SecretStore`: claves API en `<app_data_dir>/secrets.json`, escritura
  atómica y permisos `0600` en Unix.
- Comandos Tauri `ai_key_status`, `ai_set_key` y `ai_clear_key`. Ninguno
  devuelve la clave; el estado incluye `configured` y un hint de 4
  caracteres.
- Diálogo **AI Keys** en la toolbar, única vía de entrada de claves.
- `ParamField` tipo `textarea` (renderizado en el Inspector) para
  prompts e instrucciones de sistema.
- Test de integración `ai_node_output_feeds_downstream_split`
  (AI-TEST-006): `literal.string` (fila CSV) → `ai.completion` →
  `string.split` → `array.length` → `io.output`, contra
  `MockGateway` (offline y determinista).
- Panel lateral **Logs** (botón en la toolbar, se abre solo al fallar un
  run): todas las entradas de la última ejecución, con filtro por nivel,
  búsqueda por label / kind / nodo / valor, expansión al JSON completo y
  **Copy** para volcar el run entero como texto.
- `EvalCtx::debug/info/warn/error(label, value)` como API de una línea
  para que cualquier nodo escriba en el log del run; la entrada recuerda
  `node_id` y `kind` automáticamente.
- `LogEntry` gana `level` (`debug|info|warn|error`) y `kind`.
- `io.logger` acepta un param `level` (select) además de `label`.
- `docs/ARCHITECTURE/decisions.md` con las decisiones ADR-001…ADR-004.

## Fixed

- Los logs de un run fallido se descartaban al devolver `Err`: el
  diagnóstico de los nodos ya ejecutados se perdía justo cuando hacía
  falta. El runner devuelve ahora `RunFailure { error, logs, stats }` y
  `run_blueprint` lo serializa como `RunOutcome` (`ok: false`), que la UI
  pinta en el panel lateral.

## Changed

- `run_graph` es ahora `async` y el comando `run_blueprint` también. Se
  añadió `run_graph_with(bp, inputs, gateway)` para inyectar el gateway;
  `run_graph` sigue existiendo como entrada sin gateway.
- Nuevo registro `setup_async_registry()` en `executor/nodes/mod.rs`.
  `NodeExec` (punteros a función) queda intacto para los 37 nodos
  síncronos.
- `catalog.ts`: categoría `AI` y color propio.

## Known issues

- `cargo test --lib` mantiene 3 fallos preexistentes en
  `executor::nodes::file_iterate_folder` (pasan una ruta de fichero a
  `fs::read_dir`). Ajenos a esta entrega; registrados como PROD-TECH-007.
- El prompt es texto plano: no hay todavía plantillas con variables
  (`{{...}}`) ni salida estructurada (JSON schema).
- No hay cancelación de un run en curso: un `ai.completion` lento bloquea
  el resto del grafo hasta que el proveedor responde o falla.
